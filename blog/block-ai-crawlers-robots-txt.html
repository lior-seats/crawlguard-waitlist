How to Block GPTBot, ClaudeBot & AI Crawlers in robots.txt (2026 Guide)

September 2026 · 8 min read · Check your site free →

AI crawlers from OpenAI, Anthropic, Meta, ByteDance, and others are crawling the web to build training datasets. If your site is publicly accessible, there's a good chance multiple AI bots are visiting it right now — consuming your bandwidth, burning through your Vercel/Cloudflare/AWS budget, and contributing to someone else's AI model without your consent.

The good news: you can block them in 5 minutes using your robots.txt file. This guide covers every major AI crawler, with copy-paste rules and verification steps.

The quick version: block all major AI crawlers

Add this to your robots.txt file to block all known AI training crawlers at once:

# Block all major AI training crawlers

# OpenAI
User-agent: GPTBot
Disallow: /

# Anthropic
User-agent: ClaudeBot
Disallow: /
User-agent: anthropic-ai
Disallow: /

# Meta / Facebook
User-agent: meta-externalagent
Disallow: /
User-agent: FacebookBot
Disallow: /

# ByteDance / TikTok
User-agent: Bytespider
Disallow: /

# Perplexity AI
User-agent: PerplexityBot
Disallow: /

# Common Crawl (used for many AI datasets)
User-agent: CCBot
Disallow: /

# Google Extended (AI training opt-out, separate from search)
User-agent: Google-Extended
Disallow: /

# Apple AI
User-agent: Applebot-Extended
Disallow: /

⚠️ Important: Google-Extended is NOT Googlebot

Blocking Google-Extended does NOT affect your Google Search ranking. It only opts you out of Google's AI (Gemini) training data. Your regular search indexing is controlled by Googlebot. You can safely block Google-Extended without any SEO impact.

Where is your robots.txt file?

Your robots.txt must live at the root of your domain: https://yourdomain.com/robots.txt

Next.js

// app/robots.ts (Next.js 13+ App Router)
import { MetadataRoute } from 'next'

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      { userAgent: 'GPTBot', disallow: '/' },
      { userAgent: 'ClaudeBot', disallow: '/' },
      { userAgent: 'anthropic-ai', disallow: '/' },
      { userAgent: 'meta-externalagent', disallow: '/' },
      { userAgent: 'Bytespider', disallow: '/' },
      { userAgent: 'PerplexityBot', disallow: '/' },
      { userAgent: 'CCBot', disallow: '/' },
      { userAgent: 'Google-Extended', disallow: '/' },
      { userAgent: '*', allow: '/' },
    ],
    sitemap: 'https://yourdomain.com/sitemap.xml',
  }
}

Static sites (GitHub Pages, Netlify, Vercel)

Create a file named robots.txt in your public/static folder with the rules at the top of this guide. For Vercel, place it in /public/robots.txt. For GitHub Pages, place it in the root of your repository.

WordPress

In WordPress, go to Settings → Reading → Search Engine Visibility, then use a plugin like Yoast SEO or RankMath to add custom robots.txt rules. Alternatively, edit robots.txt directly at the root of your WordPress installation via FTP/SSH or your hosting file manager.

Does robots.txt actually work?

Mostly yes — with important nuances:

  • OpenAI (GPTBot): Respects robots.txt since August 2023. Confirmed compliance.
  • Anthropic (ClaudeBot): Respects robots.txt. Also supports the anthropic-ai User-Agent for direct model requests.
  • Google-Extended: Respects robots.txt. Google explicitly created this separate User-Agent so you can opt out of AI training without affecting search.
  • Meta (meta-externalagent): Respects robots.txt as of 2023.
  • Bytespider: Compliance is inconsistent. Some reports of ignoring disallow rules. Consider rate-limiting at the server level as well.
  • CCBot (Common Crawl): Generally respects robots.txt but runs on a 6-week crawl cycle — changes may take time to take effect.

⚠️ robots.txt is advisory, not enforced

Any crawler can technically ignore your robots.txt. If you're dealing with aggressive or non-compliant bots, you'll need server-level blocking (Cloudflare WAF rules, nginx deny rules, or a monitoring tool that alerts you when bots reappear). robots.txt works for compliant bots — and all major AI labs have committed to honoring it.

Server-level blocking for non-compliant crawlers

If robots.txt isn't enough (particularly for Bytespider or other aggressive crawlers), you can block at the infrastructure level:

Cloudflare (free tier)

# Cloudflare WAF Custom Rule (Firewall → WAF → Custom Rules)
# Field: User Agent · Operator: contains · Value: Bytespider
# Action: Block

# Or use the pre-built "Bot Fight Mode" for automated bot blocking

nginx

# In your nginx.conf or server block:
map $http_user_agent $block_ai_crawlers {
    default         0;
    ~*GPTBot        1;
    ~*ClaudeBot     1;
    ~*anthropic-ai  1;
    ~*Bytespider    1;
    ~*PerplexityBot 1;
    ~*CCBot         1;
}

server {
    if ($block_ai_crawlers) {
        return 403;
    }
}

Frequently asked questions

Will blocking AI crawlers hurt my SEO?

No — as long as you don't block Googlebot or Bingbot. AI training crawlers (GPTBot, ClaudeBot, Google-Extended, etc.) are completely separate from search indexing. Blocking them has zero effect on your search rankings.

Does blocking AI crawlers reduce my bandwidth costs?

Yes, significantly. Developers have reported Vercel bandwidth bills increasing 5-20x due to AI crawlers — particularly Bytespider and GPTBot. Blocking them in robots.txt won't stop the requests (the crawler has to fetch robots.txt first), but it does dramatically reduce repeat crawling of all your content pages. For full bandwidth protection, combine robots.txt with server-level blocking.

How often do AI crawlers visit my site?

It varies by crawler. GPTBot typically crawls on a multi-week cycle. Bytespider and PerplexityBot are often more aggressive. The only way to know for sure is to check your server access logs or use a monitoring tool. I updated my robots.txt. How long until crawlers stop?

GPTBot and ClaudeBot typically re-check robots.txt before each crawl session and will stop relatively quickly (days). CCBot runs on a 6-week cycle, so it may take longer. Bytespider compliance is unpredictable — if you need immediate results, use server-level blocking.
